### 2) Pragmatic fix (drop-in patch pattern)

Below are two concrete functions: `brutal_task_kill()` — which now does the synchronous free/compaction — and `k_reaper_task()` reduced to TCB cleanup only. **Adapt locking and names to your codebase** but this is a ready-to-implement pattern.

```c
// --- brutal_task_kill: perform immediate memory reclamation ---
// adapt types / lock names to your codebase
void brutal_task_kill(task_t *t) {
    // 0) Log early
    log_info("[KILL] '%s' (id=%d) - beginning brutal_task_kill", t->name, t->id);

    // 1) Mark as zombie so other subsystems skip it
    scheduler_lock();            // ensure safe state transitions if you have a scheduler lock
    t->state = TASK_ZOMBIE;
    scheduler_unlock();

    // 2) Ensure task is not running anywhere (RP2040: send IPI to other core, remove from runqueues)
    // Example: ipi_stop_task_if_running(t);
    stop_task_on_other_cores_and_remove_from_runqueues(t);

    // 3) Free the memory owned by that task right now.
    //    Acquire memory allocator lock (use same lock ordering as other callers).
    memory_lock();
    // free_task_memory should:
    //   - free the stack pages
    //   - free any heap allocations tracked as owned by this task
    //   - update global accounting (used_bytes, free_bytes)
    free_task_memory(t);
    memory_unlock();

    // 4) Compact memory to increase chance waiting kmalloc will succeed on retry
    //    Make sure mem_compact() doesn't grab scheduler_lock or deadlock with free.
    mem_compact();

    // 5) Notify any alloc waiters / wake threads blocked on alloc.
    //    If kmalloc may block/wait, wake them. If it retries immediately, this may be enough.
    wake_alloc_waiters();

    // 6) Keep TCB removal for reaper OR optionally remove minimal TCB fields here.
    //    Reaper should still remove the TCB entry and other bookkeeping.
    log_info("[KILL] '%s' (id=%d) memory freed; left TCB for reaper cleanup", t->name, t->id);
}
```

And the reaper becomes a simple cleanup task that only removes TCBs and stale bookkeeping:

```c
void k_reaper_task(void) {
    while (1) {
        // old code freed memory here; that part is now removed.
        // reaper now only clears TCB slots and other meta (no heap frees).
        reap_zombie_tcbs();
        log_debug("[REAPER] cleaned TCBs; sleeping...");
        sleep_ms(REAPER_PERIOD_MS);   // e.g., 5s or whatever you use
    }
}
```

**Important notes for this patch:**

* Keep lock ordering consistent: if `brutal_task_kill()` takes `scheduler_lock` then `memory_lock`, never do the reverse elsewhere — otherwise you risk deadlocks.
* `mem_compact()` can be expensive; measure or move compaction to a deferred path if latency is a problem.
* If other cores or kernel subsystems can still touch the task's memory, you must ensure they are quiesced before `free_task_memory()` runs (IPIs or per-core run-queue removal).
* If `mem_free()` can sleep, ensure `brutal_task_kill()` runs in a context that is allowed to sleep.

### 3) Prioritized checklist: hardening `kmalloc` & allocator

Put these in order — first three are the highest-impact, fastest wins.

1. **Synchronous free in kill path** (as above). This fixes the double-OOM immediate race.
2. **Make `kmalloc` return NULL instead of retry-panic** (or at least give a configurable policy). Panics on OOM are useful for some kernels but very unforgiving for tiny MCUs. If you must panic, add better telemetry before panic.
3. **Atomic accounting**: ensure all alloc/free update the same global counters under the same lock. Any mismatch = phantom memory.
4. **Block/wait for reclaimer**: if you cannot free synchronously, make kmalloc optionally block on a condition variable until reaper finishes (or until timeout) — better than immediate second OOM.
5. **Add alloc wait/wakeup**: when reclaimer finishes freeing, it should `wake_alloc_waiters()` so blocked callers can retry.
6. **Small-block allocator (size-classes)**: for many microcontrollers, a slab/pool allocator for small chunks (like 16/32/64/128/256 byte pools) dramatically reduces fragmentation compared to a general-purpose first-fit.
7. **Coalescing & boundary tags**: if you use free list with variable sizes, coalesce neighboring free blocks on free.
8. **Double-free / corrupt detection**: add a small header magic and size check in `kfree()` to catch bogus frees.
9. **Instrumentation**: counters for `alloc_attempts`, `alloc_failures`, `oom_kills`, `mem_compact_calls`, `mem_total_bytes`, `mem_used_bytes`. Logging with timestamps helps root cause.
10. **Unit / fuzz tests**: tiny tests that randomly alloc/free many small blocks, plus two-core concurrency stress, plus forced OOM sequences.

### Example defensive `kmalloc` behavior (policy)

If you want a robust `kmalloc` that won’t panic the kernel in subtle races:

* Try allocation (fast path).
* If fails: attempt `mem_compact()` (cheap).
* If still fails: call `attempt_reclaim()` (synchronous killer or wake reaper and wait up to X ms).
* After reclaim/wait, try allocation again once and then return NULL if still fails (or escalate to panic only if policy demands).

This prevents quick double-OOMs and gives the system a chance to recover.
